# Release notes

## v0.1（2026/11/20，分支 `v0.1`，尚未合併）

### 新增
- 專案骨架：`index.html`、`app.js`、`logic.js`（不需要 build），`config/templates/prmc-workshop.json`
- `logic.js`：B6 全部函式（tally、rankCompetition、maxVotes、mergeItems、unmerge、validateConfig、toExportJson／fromImportJson、nextPhase、dupNameWarnings），另加題目文字（T18）、PIN（T19）、小幫手編輯權限（T2、T8）、組數（T10）的檢查
- 安全規則 `database.rules.json`（OWNER_UID 已填入）
- 擁有者 `#/admin`：Google 登入（只限擁有者）、場次清單、建立場次（模板或沿用某場次的設定）、可見性、組數、設定 PIN、匯出 JSON、匯入 JSON（沿用代碼或產生新代碼；覆蓋前先自動下載備份；匯入後一律私人）
- 加入場次：參與者（姓名＋組別，同組同名要求加註記）、小幫手（PIN＋組別）、主持人（PIN）
- 小幫手收集階段：新增、修改、刪除本組題目；分類、已改寫；停止輸入 0.5 秒自動儲存；連線燈號
- 即時存檔：沒送出的草稿存在瀏覽器，重新整理或恢復連線後自動再送；場次快照讓重新整理時先顯示上次內容
- 投影畫面 `#/s/{代碼}/screen`：依組別／依分類（自動依階段，也可以手動切換）
- 主持人畫面：目前階段、各組各類題數、參與者人數、同名警示、開啟投影畫面
- 參與者畫面：等待畫面（投票功能在 v0.3）
- 本機預覽：`npm run dev`（emulator＋示範場次 TEST26，不碰正式資料）；`tools/sim-helpers.js` 模擬 5 位小幫手同時輸入

### 安全規則與規格 B5 草案的差異（待 Mike 確認後寫回 spec.md B5）
1. `sessions` 加上「擁有者可以讀整個清單」——否則 `#/admin` 列不出場次。
2. `sessions/$code`、`access/$code` 加上「擁有者可以整筆寫入、刪除」——否則無法建立、匯入（含選票與參與者）、刪除場次。
3. 選票的 `v1`～`v3`、`ts` 驗證對擁有者放寬——否則匯入舊場次時，過去的投票時間、指向已合併題目的票會被拒絕。
4. PIN 比對加上「`secrets` 裡必須真的有 PIN」——草案中，還沒設定 PIN 的進行中場次，任何人不輸入 PIN 就能當小幫手、主持人（空值＝空值）。
5. `meta/visibility` 只能是 private／live／demo；`meta/groupCount` 只能是 1～8。

### 已知限制
- 同一個瀏覽器的所有分頁共用同一個登入身分：在同一台電腦同時當兩組小幫手會互相覆蓋。實際使用時每位小幫手各用自己的裝置即可。
- PIN 沒有嘗試次數限制（6 位數字），內部工作坊可以接受；當天結束後換 PIN 或切回私人即可。
- 「刪除場次」在 v0.4（要先做自動備份）；合併、拆回、階段切換在 v0.2；投票、結果、XLSX、QR code 在 v0.3。
- 本機預覽的擁有者登入是測試帳號（不會跳出 Google 視窗）；正式網站用 Google 跳出視窗登入。
